# TV Mute — мини-приложение для кнопки Mi на Xiaomi Mi TV

Дата: 2026-11-21
Статус: на согласовании

## Зачем

Button Mapper (flar2.homebutton 3.35) на телевизоре перехватывает все клавиши и обрабатывает их
через Accessibility. Из-за этого тормозит вся навигация (пульт «зависает», переходы влево-вправо
долгие), а на кнопке Mi к тому же баг: первое нажатие срабатывает, второе проходит мимо маппера и
запускает штатный PatchWall.

Нужно: убрать Button Mapper и заменить его минимальным сервисом, который реагирует **только** на
кнопку Mi, не трогая остальные кнопки.

## Цели

- Короткое нажатие кнопки Mi → mute/unmute звука телевизора.
- Удержание кнопки Mi (по умолчанию 500 мс) → штатное действие: запуск PatchWall
  (`com.mitv.tvhome.atv/.app.BannerLogoB`).
- Ноль влияния на остальные кнопки пульта.
- Сборка и установка локально, без Google Play, без root.

## Не-цели

- Ремап других кнопок.
- Красивый UI, настройки, профили, локализации.
- Работа без включённой службы доступности.

## Анти-цели (считаем провалом)

- Любая задержка на чужих кнопках или на навигации.
- Двойное срабатывание (mute + PatchWall одновременно).
- Зависимость от Button Mapper.

## Ограничения

- Телевизор: MiTV-MSSP1, Android 9 (API 28), сборка `user`, root отсутствует.
- Кнопка Mi приходит как Linux `KEY_YELLOW`; Android-код в системе — **191** (подтверждено логом
  `GlobalKey: receive ACTION_GLOBAL_BUTTON keyCode = 191` и отображением Button Mapper).
- Штатное действие кнопки — `GlobalKeyReceiver.startPatchWall()`: запуск
  `com.mitv.tvhome.atv/.app.BannerLogoB` (проверено `am start`, работает без extras).
- Accessibility-сервис не может вернуть потреблённую клавишу системе, поэтому «действие по
  умолчанию» долгого нажатия воспроизводим явным запуском activity.
- На ПК нет JDK; для сборки нужен портативный JDK 17 (Temurin zip, без админа) в `tools/`.
- Android SDK build-tools 34/35 и platform android-35 уже есть.

## Рассмотренные подходы

| Вариант | Итог |
|---|---|
| **A. Своё мини-приложение** (AccessibilityService) | **Выбран.** Трогает только код 191, остальные клавиши сразу пропускает; задержка на короткое нажатие ~0. |
| B. tvQuickActions | Платный, широкая функциональность и разрешения; выигрыш по лагу не гарантирован. |
| C. Key Mapper | Телефонный UI, известные проблемы на Android TV, фильтрует все клавиши. |
| D. Root + keylayout | Невозможно: root нет. |

## Как работает (дизайн)

**Пакет:** `ru.digit.tvmute`, имя «TV Mute», minSdk/targetSdk 28, подпись debug-ключом.

**Компоненты:**
1. `MuteAccessibilityService` — единственная рабочая часть.
2. `SetupActivity` — простой экран: статус службы + кнопка «Открыть настройки доступности».
   Нужен только для включения службы; иконка в лаунчере.

**Логика `onKeyEvent`:**
- Если `keyCode != 191` → `return false` немедленно (никакой обработки, нулевой оверхед).
- `ACTION_DOWN`, `repeatCount == 0` → запомнить время, поставить таймер 500 мс, `return true`.
- Повторные `ACTION_DOWN` → `return true`, игнорировать.
- Таймер сработал при удержании → запустить PatchWall, пометить «долгое сработало».
- `ACTION_UP`:
  - если долгое уже сработало → ничего;
  - иначе отменить таймер и переключить mute → `return true`.
- `ACTION_CANCEL` → сбросить состояние.

**Mute:** `AudioManager.adjustStreamVolume(STREAM_MUSIC, ADJUST_TOGGLE_MUTE, 0)`.
Риск: на Xiaomi системный mute глушит несколько потоков. Если STREAM_MUSIC окажется недостаточно,
глушим/восстанавливаем набор потоков (MUSIC, SYSTEM, VOICE_CALL) с учётом текущего состояния.
Проверяется на живом ТВ до фиксации.

**Диагностика:** в logcat под тегом `TVMute` пишется каждый полученный код клавиши, длительность
нажатия и выполненное действие. Это позволит подтвердить код 191 на первом запуске.

## Сборка

`build.ps1`:
1. Скачать Temurin JDK 17 zip в `tools/` (если нет).
2. `aapt2 compile/link` ресурсов и манифеста против `android-35` (`android.jar`).
3. `javac` → `d8` → dex.
4. Упаковать APK, `zipalign`, подписать `apksigner` (keystore в `keystore/`, создаётся один раз).
5. Вывести путь к APK.

## Проверка

1. Установить APK, включить службу (через `SetupActivity` или adb `settings put secure
   enabled_accessibility_services ru.digit.tvmute/.MuteAccessibilityService`).
2. Инъекция короткого нажатия (`sendevent ... KEY_YELLOW`) → mute переключается, в logcat действие
   «mute».
3. Инъекция удержания 1–2 с → открывается PatchWall, mute не переключается.
4. Физические нажатия: 3 коротких подряд → звук переключается каждый раз; 2 удержания → PatchWall.
5. Навигация: стрелки/OK/назад — субъективно без задержек; в logcat по этим клавишам нет записей.
6. Отключить Button Mapper (`pm disable-user --user 0 flar2.homebutton`), повторить п. 2–5.

## Откат

- Отключить нашу службу, удалить `ru.digit.tvmute`.
- Включить Button Mapper обратно (`pm enable flar2.homebutton`) — его настройки сохранились.

## Что решено (мои допущения)

- Порог долгого нажатия: **500 мс** (согласовано).
- Срабатывание долгого — по таймеру, не дожидаясь отпускания.
- Никаких пользовательских настроек в первой версии; константы в коде.
- Button Mapper после установки **отключается**, не удаляется.
